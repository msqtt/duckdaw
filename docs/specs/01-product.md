# DuckDAW 产品规格

## 1. 产品定位

DuckDAW 是一个轻量、可爱、低门槛的浏览器数字音频工作站（DAW）。用户无需安装桌面软件，即可在单页应用中创建 MIDI 与音频轨道、编辑编排、混音、保存工程并导出可分享的音频。

产品优先级依次为：

1. **作品不丢失**：保存、加载和恢复必须可靠；
2. **核心创作闭环**：创建 → 编排 → 试听 → 编辑 → 混音 → 导出；
3. **低学习成本**：常见操作可发现，快捷键与专业 DAW 习惯一致；
4. **本地优先**：工程和音频默认在用户设备处理，远端同步必须由用户主动触发；
5. **渐进增强**：不支持高级浏览器 API 时提供清晰降级路径。

## 2. 目标用户

- **初学者**：希望快速制作节奏、旋律和简单歌曲，不需要复杂工程配置。
- **音乐创作者**：需要在任意设备快速记录想法并导出音频。
- **教学与演示用户**：需要一个无需安装、结构清晰的 DAW 示例。

当前版本不以大型商业制作、超低延迟现场演出或第三方插件宿主为目标。

## 3. 核心用户价值

- 直接在浏览器中创建 MIDI 与音频内容；
- 用统一时间轴组织多轨作品；
- 用钢琴卷帘编辑音高、位置、长度与力度；
- 用混音器调整音量、声像、静音、独奏、包络和基础效果；
- 将工程保存为可移植的单文件包；
- 将作品导出为常见音频格式；
- 可选地把工程同步到用户自己的 GitHub 仓库。

## 4. 核心用户流程

### 4.1 新建并制作 MIDI 作品

1. 用户新建工程或打开默认工程。
2. 添加 MIDI Track，选择或沿用默认乐器。
3. 在轨道空白处创建 MIDI Clip。
4. 打开 Piano Roll，添加、选择、移动、缩放或量化音符。
5. 播放试听，并调整 BPM、循环区、节拍器和混音参数。
6. 保存 `.duckdaw` 工程，或导出 WAV/MP3/OGG。

成功标准：重新加载已保存工程后，用户可继续编辑且声音与保存前等价。

### 4.2 导入或录制音频

1. 用户添加 Audio Track，或把浏览器支持的音频文件拖入时间轴。
2. 系统解码音频并按当前 BPM 计算片段拍长。
3. 用户可移动、复制和调整片段长度。
4. 用户也可授权麦克风，在已选 Audio Track 上录音。
5. 保存工程时，音频二进制被内嵌到工程包。

成功标准：关闭页面后重新打开工程，音频片段仍可播放，不依赖旧的 `blob:` URL。

### 4.3 保存、恢复与分享

1. 首次保存优先使用 File System Access API；不支持时下载 `.duckdaw` 文件。
2. 后续保存写回同一文件；另存为创建新文件。
3. 用户可从最近项目、文件选择器、设置中的导入入口或 GitHub 加载。
4. 加载必须先验证格式，再原子替换当前工程；失败不得破坏当前工程。
5. 未保存更改通过项目名旁 `*` 和离页提示告知用户。

### 4.4 导出最终音频

1. 用户选择格式、采样率与导出区域。
2. 应用离线渲染 MIDI 和音频轨道，应用静音/独奏、音量、声像和效果。
3. WAV 直接下载；MP3/OGG 经 FFmpeg 编码后下载。
4. 导出不应改变工程脏状态，也不等同于工程保存。

## 5. 当前版本范围

### 5.1 范围内

- MIDI 与 Audio 两类轨道；
- 时间轴、片段、标记、循环和缩放；
- 钢琴卷帘和基础音符编辑；
- 麦克风录音与音频文件导入；
- 基础合成器/鼓音色、ADSR、reverb、delay；
- 轨道和主通道混音；
- `.duckdaw` 本地保存加载、最近项目、模板入口；
- WAV/MP3/OGG 导出；
- GitHub Contents API 手动同步；
- 明暗/系统主题。

### 5.2 明确不在当前交付范围

- VST/AU/Audio Unit 或任意第三方插件宿主；
- 实时多人协作；
- 完整 MIDI 文件导入导出；
- 外部 MIDI 设备录制；
- 总线/编组/任意路由；
- Automation、Tempo Track 编辑、音频拉伸和专业母带；
- 移动端完整编辑体验；
- 服务端账号、云存储或跨设备冲突解决。

上述能力可作为规划项，但不得在当前功能说明中宣称可用。

## 6. 体验与质量目标

### 6.1 可靠性

- 任何成功提示都必须对应已完成的持久化或导出操作。
- 加载失败时保留加载前工程。
- 工程文件不得持久化不可跨会话使用的 `blob:` URL。
- 每个异步操作都应有进行中状态，避免重复提交。

### 6.2 性能

目标基线为桌面 Chromium 的最新两个稳定版本：

- 含 20 条轨道、200 个片段、10,000 个音符的工程，基本编辑应保持可交互；
- 长操作（打包、加载、渲染、编码）不得永久阻塞 UI，且必须展示进度或忙碌状态；
- 音频节点和对象 URL 在工程替换、轨道删除或组件卸载后应释放。

这些是验收目标；当前代码尚无完整性能基准。

### 6.3 浏览器支持

- **推荐**：支持 Web Audio、MediaRecorder、IndexedDB 和 File System Access API 的桌面 Chromium。
- **降级**：缺少 File System Access API 时，允许文件下载和 `<input type=file>` 导入。
- **权限**：麦克风仅在用户明确操作后申请；被拒绝时恢复录音状态并给出可行动提示。
- **非目标**：不保证 iOS/Safari 上所有录音、编码和文件句柄能力一致。

### 6.4 可访问性与一致性

- 所有纯图标按钮必须有可读标签或 `aria-label`/`title`；
- 键盘快捷键不得在文本输入时误触发，保存/打开除外；
- 删除等破坏性操作需要确认，且提示必须与撤销能力一致；
- 亮色、暗色和系统主题下关键信息应有足够对比度。

## 7. 产品成功标准

当前阶段以可验证的闭环质量为主，不以用户增长为主：

- 核心新建—编辑—保存—重载—导出流程通过端到端验收；
- 工程往返测试覆盖全部持久化字段和内嵌音频；
- P0 数据完整性缺口清零；
- 不再存在“按钮可点击但没有产出”的核心入口；
- specs 中每个“已实现”需求至少关联一个自动化测试或人工验收步骤。
