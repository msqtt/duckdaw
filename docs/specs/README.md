## 2. 权威性

发生冲突时按以下顺序处理：

1. `docs/specs/04-project-format.md` 对工程文件格式具有最高优先级；
2. `docs/specs/02-functional-requirements.md` 对用户可见行为具有最高优先级；
3. `docs/specs/03-technical-design.md` 约束实现方式和不变量；
4. `docs/specs/05-delivery-plan.md` 记录现状，不改变目标需求；
5. `docs/` 下其余文档均为历史设计、分析或验证记录，不作为当前实现状态的唯一依据。

若代码与规范不一致，不应静默修改规范以迎合缺陷；应在交付计划中记录差距，并决定修代码或显式变更需求。

## 3. 状态定义

功能需求使用以下状态：

- **已实现**：当前主路径可用，并与该条验收标准基本一致；
- **部分实现**：已有 UI 或底层能力，但存在数据丢失、语义偏差、兼容性或关键交互缺口；
- **未实现**：代码中不存在可用主路径，或只有无实际效果的入口；
- **规划**：目标需求，尚未进入当前版本承诺。

“已实现”不是质量永久保证；最终状态必须由自动化测试或明确的人工验收记录支持。

## 4. 术语

- **工程（Project）**：项目元数据、传输设置、轨道、片段、标记、编排与资源的集合。
- **轨道（Track）**：MIDI 或 Audio 类型的通道，包含音量、声像、静音、独奏及效果参数。
- **片段（Clip）**：位于全局时间轴上的内容单元；MIDI 片段包含音符，Audio 片段引用音频资源。
- **音符（Note）**：以片段局部拍位置表示的 MIDI 音符事件。
- **编排（Arrangement）**：一组独立的时间轴内容。当前代码只有名称和活动 ID，目标语义见 FR-ARR。
- **拍（beat）**：内部时间轴基础单位，当前界面按四分音符解释；小节换算不得永久假定每小节 4 拍。
- **工程保存（Save Project）**：写出可再次编辑的 `.duckdaw` 工程文件。
- **音频导出（Export Audio）**：离线渲染为 WAV/MP3/OGG；不等同于保存工程。

## 5. 需求维护规则

1. 所有用户可见能力必须有稳定 ID（如 `FR-PROJ-01`）。
2. 新需求必须说明状态、前置条件、成功路径、失败反馈和可验证结果。
3. 数据结构变化必须同步更新 `04-project-format.md`，并说明迁移策略。
4. 涉及权限、令牌、麦克风或远端写入时，必须补充安全与隐私要求。
5. 功能完成时，应同步更新 `05-delivery-plan.md` 的状态和测试证据。
6. 不得把仅有按钮、状态位或占位字段的能力标记为“已实现”。

## 6. 当前实现摘要

当前可用主路径包括：浏览器内 MIDI/Audio 多轨编排、钢琴卷帘编辑、音频导入与麦克风录音、基础混音和效果、传输/循环/节拍器、离线音频导出、`.duckdaw` ZIP 保存加载、最近项目、GitHub 同步、标记和主题。

主要已知偏差包括：工程包仍缺少严格 schema/版本校验；无 IndexedDB 恢复快照；模板保存的是完整工程而非结构模板；Arrangement 不隔离片段；MIDI 录音未采集输入；撤销仅追踪 `tracks`、`clips`、`bpm`。详见 `05-delivery-plan.md`。
